# 乡音地图 Design I/O

这组文档把产品要求、HarmonyOS 设计约束和真机反馈转成可执行的设计契约。

## 阅读顺序

1. `spec.md`：先确认产品目标、主流程和验收边界。
2. `domain.md`：理解乡音数据的业务含义和可信表达。
3. `craft.md`：确定排版、层级、反馈、动效和无障碍底线。
4. `design-system.md`：查视觉角色和 Token 使用规则。
5. `components.md`：查组件语义、状态和组合边界。
6. `responsive-template.md`：查手机、折叠屏和平板页面骨架。
7. `evaluator.md`：在构建和真机验收时逐项检查。
8. `gaps.log`：确认哪些能力仍是模拟、未验证或未完成。

## 证据标签

- `[官方规范]`：来自 HarmonyOS 设计要求或系统交互约束。
- `[项目事实]`：当前工程代码、资源、配置或构建记录能够证明。
- `[设计推断]`：根据当前产品目标作出的方案，需要通过真机或用户测试验证。
- `[待开发验证]`：不能仅凭设计或静态代码证明的 SDK、权限和运行能力。

## 单一事实源

- 完整产品范围：`../spec.md`
- 完整 HarmonyOS 交付：`../harmonyos-design-handoff.md`
- 构建与运行记录：`../verification.md`
- 本目录只维护执行规则，不复制签名、SDK 或构建配置。
