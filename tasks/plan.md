# 实施计划：乡音地图 HarmonyOS App

## 概述

在 `/Users/bjl/DevEcoProjects/dialect-map-harmonyos` 维护 HarmonyOS Stage 模型工程，以 ArkTS/ArkUI 实现地图首页、乡音群聊、模拟录音鉴定和乡音护照核心流程。地图先显示本地底图，Map Kit 仅在在线底图与 Marker 成功后接管；AI、同乡和群聊内容仍为本地演示并在界面中明确标注。仓颉领域层依据本地 CangjieSkills 建立独立契约，但在本机缺少 `cjc/cjpm` 时不接入 HarmonyOS 构建链，也不声称编译成功。

## 架构决策

- 使用单 `entry` 模块与 ArkUI 页面路由，避免为 Demo 引入不必要的模块复杂度。
- 首页默认使用可拖动、缩放和复位的本地地图；底图与点位共用经纬度投影，Map Kit 在线底图和 Marker 均成功后才接管。
- 页面只依赖确定性的本地模拟服务；接口命名保留未来地图、鉴定和社交后端替换点。
- 群聊默认进入“会话”（已加入群组）；推荐和按方言只作为发现入口。本人消息仅保留本次运行，不连接社交后端。
- 鉴定状态使用有限枚举，分数始终限制在 `0..100`。
- 乡音护照由鉴定结果生成，避免维护两套会漂移的用户数据。
- 仓颉领域层与 ArkTS UI 通过文档化数据契约隔离；工具链可用后再实现 FFI 或共享序列化集成。
- 不采用用户已明确拒绝的科幻地球、强光效或原稿卡片视觉；只延续已确认的“地图主视觉 + 底部抽屉”交互原则。

```text
  └── 工具链安装后才能编译与接入
```

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 当前 SDK 与工程模板版本不一致 | 高 | 先用最小骨架执行真实 Hvigor 构建，再扩展页面 |
| Map Kit 或定位在设备/权限状态下不可用 | 中 | Map Kit 失败回退本地地图；拒绝定位后继续全国浏览 |
| 仓颉工具链缺失 | 高 | 领域层独立保存，标记未编译，不阻塞 ArkTS Demo |
| 模拟 AI 被误认为真实能力 | 高 | 结果页和文档同时显示“模拟鉴定” |
| 当前 unsigned HAP 不能直接覆盖安装 | 中 | 签名材料只保留在用户本机配置，不写入受跟踪文件；构建与运行分开报告 |
