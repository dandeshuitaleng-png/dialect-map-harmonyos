# 实施计划：乡音地图 HarmonyOS App

## 概述

在 `/Users/bjl/DevEcoProjects/dialect-map-harmonyos` 新建 HarmonyOS Stage 模型工程，以 ArkTS/ArkUI 实现地图首页、模拟录音鉴定和乡音护照三段核心流程。地图、AI 结果和同乡数据首版均为本地模拟，并在界面中明确标注。仓颉领域层依据 CangjieSkills 建立独立契约，但在本机缺少 `cjc/cjpm` 时不接入 HarmonyOS 构建链，也不声称编译成功。

## 架构决策

- 使用单 `entry` 模块与 ArkUI 页面路由，避免为 Demo 引入不必要的模块复杂度。
- 首页地图使用本地地图资产和 ArkUI 手势组合模拟平移、缩放和恢复定位，不接入地图 SDK 或 Token。
- 页面只依赖确定性的本地模拟服务；接口命名保留未来地图、鉴定和社交后端替换点。
- 鉴定状态使用有限枚举，分数始终限制在 `0..100`。
- 乡音护照由鉴定结果生成，避免维护两套会漂移的用户数据。
- 仓颉领域层与 ArkTS UI 通过文档化数据契约隔离；工具链可用后再实现 FFI 或共享序列化集成。
- 不采用用户已明确拒绝的科幻地球、强光效或原稿卡片视觉；只延续已确认的“地图主视觉 + 底部抽屉”交互原则。

## 依赖关系

```text
工程骨架
  └── 展示模型与模拟服务
       ├── 地图首页
       │    └── 同乡列表 → 乡音护照
       └── 录音鉴定 → 点亮地区 → 当前用户乡音护照

仓颉数据契约（独立）
  └── 工具链安装后才能编译与接入
```

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 当前 SDK 与工程模板版本不一致 | 高 | 先用最小骨架执行真实 Hvigor 构建，再扩展页面 |
| 地图交互在不同 ArkUI API 版本下不可用 | 中 | 优先使用基础手势与状态变换，不依赖实验性 API |
| 仓颉工具链缺失 | 高 | 领域层独立保存，标记未编译，不阻塞 ArkTS Demo |
| 模拟 AI 被误认为真实能力 | 高 | 结果页和文档同时显示“模拟鉴定” |
| 未签名 HAP 无法安装 | 中 | 将“构建产物”和“设备运行”分开报告 |
